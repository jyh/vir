# L4-E2's N4, written out (erratum L4-E2, part (4)): F₄ and the two-router program

Written 2026-11-06 by vir, in the same commit series as row L4-E2 of `ERRATA-L4.md`, BEFORE either arm's first N4 proof. Both arms take
exactly these terms. The macros `RD32`, `EXIT`, `EMIT` are `inputs/L3-programs.md`'s, expanded textually, with `w` the thread's
world. NW = 64, NS = 4, NT = 4, A = 67, as L3 pinned them.

## The regions
- each thread's world `wᵢ` is an 83-cell region holding L3's cells 0 … 82 (LEN, CODE, PAY, the wire, the ACL), laid out as L3's `world`;
- `b` is a 4-cell region holding L3's cells K … K+3 (the buckets): cell s holds sender s's tokens. It lives behind the lock `ℓb`,
  whose invariant is `inv(v₀ v₁ v₂ v₃) := every vᵢ ≥ 0`.

## F₄ (free variables `w : cap`, `ℓb : lock`; Γ ; Δ = (w : cap, ℓb : lock) ; {w}; type `cap`)
```
let n:int ← load(w, 0) in
if le(24, n) then
  RD32(0, magic) RD32(4, sender) RD32(8, topic)
  let a:int ← load(w, add(A, add(mul(sender, NT), topic))) in
  let b:cap ← acquire(ℓb) in
  let t:int ← load(b, sender) in
  if and(eq(magic, 1297303345), and(eq(a, 1), lt(0, t))) then
    let b1:cap ← store(b, sender, sub(t, 1)) in
    let r:unit ← release(ℓb, b1) in EMIT
  else
    let r:unit ← release(ℓb, b) in EXIT(2)
else EXIT(1)
```
Changed from L3's F, and nothing else: the `acquire` line is added before the bucket load. The bucket load and store address `b` at
offset `sender` instead of `w` at `add(K, sender)`. A `release` is added on both paths out of the inner `if`. `EMIT[w1/w]` becomes
`EMIT`, because the decrement no longer writes `w`. The critical section runs from the bucket load to the bucket store, so no second
thread can read a token between them.

## N4 (free variables `ℓb : lock`, `w₁ : cap`, `w₂ : cap`; Δ = {w₁, w₂}; type `unit`)
```
let w₁′:cap, w₂′:cap ⇐ par (F₄[w₁]) (F₄[w₂]) in
let u₁:unit ← free(w₁′) in
let u₂:unit ← free(w₂′) in
ret ()
```
`F₄[wᵢ]` is F₄ with `w` renamed `wᵢ` (its macro names fresh per copy). Rows, as inputs §3 states them: N4-T typed · N4-S the two sides'
triples (each keeps `ℓb`'s invariant and gives its own world L3's postcondition) · N4-V run_tokens₄ on every run, as a configuration
invariant (H5 (a)): the emits naming sender s across both threads number at most s's tokens in `b` at the start. Both triples assume
L3's `layout` precondition on their own world, including sender < NS, as L3-E1 reads R3 and R4.

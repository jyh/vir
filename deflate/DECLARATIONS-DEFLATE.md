## The oracle (X5 (a)), to be pinned BEFORE its first run
zlib's `inflate` in RAW mode (windowBits −15), built in scratch from the official release tarball. The release is named by version
and its sha256 is read at download and recorded beside the first run. Python's bundled zlib (1.2.12) is the CORPUS compressor
only, and is not the oracle.

**The protocol:**
- A stream is ACCEPTED iff `inflate` returns `Z_STREAM_END`.
- `Z_BUF_ERROR` (truncated input) and `Z_DATA_ERROR` are REJECTED.
- Bytes after the final block are ignored, as in Appendix S's S2.
- REASONS are compared and reported (D1 predicts ≥ 1 reason disagreement), never scored.

## The L2 step program (STATUS-vir 292), DECLARED BEFORE `Step.lean` EXISTS (2026-11-11, the 62nd head)
X1 (a): one decode step is the L2 program, and the loop is in the logic. These are forced by L2 as built, the same way OBJECT-L3
§1 forced the router. They are stated so that they are not found in a proof:
- **(R-a) ONE region, `world`.** `ret` gives back one capability and a product cannot carry one, so the step is a term with Δ =
  {world}, and it ends `ret world` on every path. This is L3's G2 (a) layout, taken for the same reason.
  ⇒ **The cursor record cannot be a returned value. It lives in cells of `world`**, and the step reads it with `load` and
  writes it with `store`.
- **(R-b) No loop inside a step.** A `fix` body is checked with Δ = ∅, so it cannot load. **Every step does a BOUNDED number of
  loads and stores, independent of n and OUTMAX.** Pure top-level `fix` terms (Δ = ∅) do the arithmetic between them. D4's
  `bitAt` is one such `fix`.
- **(R-c) P₂ = P₁.** There is no shift, bitwise operator, division or modulus. The bit position is kept as (byte index, bit
  index), never divided at run time.

**S-1 The layout of `world`** (cells are ints; offsets are functions of the parameters n and OUTMAX, X6):
`[ cursor | input, n cells | output, OUTMAX cells | lengths, 316 + 19 cells | three code tables (CL, L, D), each count[16] ·
first[16] · syms[288] ]`. The cursor cells are:
- mode, byte index, bit index, m (output length), BFINAL;
- a pending count (stored bytes or copy bytes left), the copy distance;
- HLIT, HDIST, HCLEN, a fill index, the last length;
- the build phase and its index;
- the reason code.

**S-2 The step's case split, by `mode`.** Each step does exactly ONE of these:
| mode | the step |
|---|---|
| HDR | read BFINAL and BTYPE, then dispatch; BTYPE 3 → REJECT |
| SHDR | align, read LEN and NLEN, check them |
| SCOPY | copy ONE input byte to the output |
| DHDR | read HLIT, HDIST, HCLEN, check them |
| CLREAD | read ONE 3-bit code-length length |
| BUILD | ONE cell of S4's construction for the current table (bl_count, then next_code, then syms, then the Kraft `left` check), the phase in a cursor cell |
| LENS | decode ONE code-length symbol (+ its extra bits); write one length or start a repeat |
| REP | write ONE repeated length |
| SYM | decode ONE literal/length symbol: a literal writes one byte; 256 ends the block; a length reads its extra bits, decodes and checks the distance, and sets the pending copy |
| COPY | copy ONE byte of a back-reference |
| DONE / REJECT | fixed points: the step returns `world` unchanged |

Fixed blocks reach BUILD with the S5 lengths written by the step itself (DEFLATE-E1's repaired reading: no completeness check
on the fixed codes). The literal reading is a separate flag, so both readings run one program.

**S-3 Decode inside one step** (S4's `decode`, ≤ 15 bits):
- load the ≤ 3 input bytes that cover the next 15 bits, and the code's count[1..15] and first[1..15] (≤ 33 loads);
- compute (ℓ, v) with a pure `fix` over those values;
- then ONE load of syms. Truncation is decided from n, a cursor cell.

**S-4 The named layer.** Step.lean carries its own named terms, compiled to de Bruijn `Tm₂` the way L3's `NT.c` does. Unlike
L3's, they have `fix`, `app` and pairs. **l1/ and l2/ are untouched (D2).** l3/ is not a dependency.

**S-5 The X3 (a) statements, fixed here and written in Safety.lean / Correct.lean BEFORE their proofs:**
- **Safety:** for every n, every OUTMAX and every byte string b (**no premise on the bytes, D7**), from the world initialised
  with b:
  - no step is an index fault;
  - the iteration reaches DONE or REJECT within a bound N(n, OUTMAX).
  The measure is what D3 scores.
- **Correctness:** the iteration reaches DONE with output o iff `inflate b OUTMAX = .ok o`, and REJECT iff `.error _`. It is
  proved by a simulation of Spec.lean (whose loops are now fuel-free by `*_adequate`).

**S-6 Reason codes** are ints in a cursor cell, one per S8 reason string, in a table in Step.lean. They are compared to S's
reasons and never scored (S8).

**What would show this declaration wrong:** a step with an unbounded number of loads; a cursor value carried outside `world`;
any edit under l1/ or l2/; a mode added after the first Step.lean proof without a line here first.

### S-7 (amendment 1 to the step declaration, 2026-11-11, the 62nd head). DECLARED before any step-mode code exists. Step.lean so far holds D4's terms, the world predicate and the named layer, and no mode.
**A mode is ADDED: `TABLE`, the INITIAL mode.** It fills a **bit table** of 2,048 cells, cell `8·b + i` = bit i of byte b, ONE
cell per step, by ONE call of D4's `BITc` (cursor cells hold the byte and bit counters, advanced with a carry). When the table is
full it moves to `HDR`. **Every later mode reads a bit as ONE `load` from the table**, at the index the cursor's byte and bit
give: `8 · input[byte] + bit`.
- **Why:** with a `fix` call per bit read, every mode's one-step lemma needs a relational split at each call, up to 15 per
  decode. With table loads every mode is a straight-line run that `simp` evaluates on a symbolic world (L3's `F_short` form).
  Exactly ONE mode then needs the `fix` lemma (`bit_steps`), once.
- **D4 is unaffected and is scored as written.** The table's every cell is computed by an L2 term (`BITc`, a top-level `fix`)
  during the run. "Bits come from something other than L2 terms" does not happen. A table SUPPLIED in the initial world, rather
  than computed by the program, would falsify D4, and it is not done.
- **The layout gains the table:** `[ cursor | bit table, 2048 | input, n | output, OUTMAX | lengths | code tables ]`. The
  cursor gains the two counters.
- **D3 is unaffected in kind:** the TABLE prefix is 2,048 steps, independent of the input. A termination measure must count
  it, and it does not involve the input cursor.

### S-8 (amendment 2 to the step declaration, 2026-11-11, the 63rd head). DECLARED before any code for the modes it touches. Step.lean holds TABLE only (`table_step`).
**A mode is ADDED: `READ`, the bit-serial reader.** Every bit a mode needs LSB-first (BFINAL, BTYPE, LEN, NLEN, HLIT, HDIST,
HCLEN, the 3-bit code-length lengths, every extra-bits field) is read by `READ`, ONE bit per step:
- cursor-2 cells hold k (bits left, ≥ 1 on entry), acc, wt (the weight of the next bit, 1 on entry) and ret (the mode to return to);
- one step: if byte < n then load v = input[byte], load x = table[8·v + bit], advance (byte, bit) with a carry, acc += x·wt,
  wt := 2·wt, k := k − 1, and when k reaches 0 set mode := ret; else reason := "truncated", mode := REJECT.
- A mode that needs a field writes (k, acc = 0, wt = 1, ret = its continuation mode) and sets mode := READ. The field is in
  acc when ret runs.
- **Consequences, stated so that they are not found in a proof:** HDR reads BFINAL and BTYPE as TWO fields, not one
  3-bit field (splitting acc into acc mod 2 and acc div 2 has no primitive under R-c): `HDR` requests 1 bit with ret
  `HDRB`, `HDRB` stores BFINAL and requests 2 bits with ret `HDRD`, `HDRD` dispatches on BTYPE: 0 → SHDR, 1 → FIXLENS, 2 → DHDR,
  3 → reason "invalid block type", REJECT). SHDR, DHDR, CLREAD, LENS and SYM likewise split at each field. Huffman DECODE
  (MSB-first, S-3) is NOT covered by this amendment; it gets its own line before its code.
- **`FIXLENS` is ADDED** (S-2 says "Fixed blocks reach BUILD with the S5 lengths written by the step itself" and named no mode
  that writes them): ONE S5 length per step into the lengths area, by the fill index, then BUILD.
- **Why:** with bit reads inline, each mode's lemma branches on truncation and on the bit carry at every read (3 reads in HDR
  alone are 27 paths before the dispatch). With READ, the truncation and carry case split is proved ONCE (`readbit_step`,
  `readbit_trunc`) and every other mode is a straight-line `simp` run with no bit read in it.
- **Layout:** cursor-2, 12 cells, sits after the bit table; the input moves after it.
  `[ cursor 0..17 | TB, TI (18, 19) | bit table 20..2067 | cursor-2 2068..2079 | input 2080.. n | output | lengths | code tables ]`.
  Cursor cells: 0 mode · 1 byte · 2 bit · 3 m · 4 BFINAL · 5 pending · 6 distance · 7 HLIT · 8 HDIST · 9 HCLEN · 10 fill ·
  11 last · 12 phase · 13 index · 14 reason · 15 n · 16 OUTMAX · 17 the literal-reading flag. Cursor-2: 2068 k · 2069 acc ·
  2070 wt · 2071 ret; 2072–2079 reserved.
- **D3:** READ adds one step per bit read; the measure still bounds it by 8·n plus a constant per field.
  **D4:** unaffected (every table cell is still computed by `BITc` in TABLE).
- **What would show this amendment wrong:** a mode other than READ that loads from the bit table; a field read whose value
  is not acc at its ret mode.

### S-9 (amendment 3, 2026-11-11, the 63rd head). DECLARED before any FIXLENS or BUILD code. A LAYOUT DEFECT in S-1, found by reading S5 against it.
- **S-1 sized the lengths area at 316 (+ 19 for CL)**, which is right for a dynamic block (HLIT ≤ 286, HDIST ≤ 30, read as ONE
  run by S's `lensLoop`) and **too small for S5's fixed codes: 288 literal/length + 30 distance = 318**. The area is now
  **318 cells, contiguous, at `IN + n + OUTMAX`**, followed by the 19 CL cells. The literal/distance split is the HLIT cell (7)
  in both cases: a dynamic block writes it from its header, and FIXLENS writes 288 (and HDIST := 30).
- **FIXLENS, one step:** with fill index i < 318, write S5's length for i at lengths[i] (i < 144 → 8, < 256 → 9, < 280 → 7,
  < 288 → 8, else 5) and advance i. At i = 318: HLIT := 288, HDIST := 30, CHK := the literal-reading flag (cell 17), build
  phase := 0, build index := 0, mode := BUILD.
- **CHK (cursor-2 cell 2072)** tells BUILD whether to run S4's checks: under DEFLATE-E1's repaired reading a fixed code is
  S4's assignment alone (CHK = 0), under the literal reading it goes through `code` with its checks (CHK = 1). A dynamic block
  sets it from its own path. BUILD's own phases, and S4's `.strict`/`.dist` variants, get their line before BUILD's code.
- **What would show this wrong:** a fixed length written outside lengths[0..318); a BUILD that reads the split from anything
  but cell 7.

### S-10 (amendment 4, 2026-11-11, the 63rd head). DECLARED before any BUILD or DECODE code: S4's construction one cell per step, and `decode` one bit per step.
**Code tables.** Three, by TARGET t (0 = CL, 1 = L, 2 = D), each 352 cells at `TB(t) = IN + n + OUTMAX + 318 + 19 + 352·t`:
`count[16] · first[16] · offs[16] · slot[16] · syms[288]`. `syms` holds the symbols in S4's order (by length, then index), so
S4's `syms[ℓ][j]` is `syms[offs[ℓ] + j]`; `slot` is the next free position per length while the code is built. (S-1 named
count · first · syms only; `offs` and `slot` are what a flat `syms` needs, R-b forbidding a per-length array of arrays.)
**Sources.** CL: the 19 cells at `IN + n + OUTMAX + 318`; L: lengths[0 .. HLIT); D: lengths[HLIT .. HLIT + HDIST).
**BUILD cells (cursor-2):** 2073 DYN (1 in a dynamic block, 0 in a fixed one) · 2074 TGT · 2075 code · 2076 left · 2077 rest
(Σ count[2..15]) · 2078 total (Σ count[1..15]). Phase in cell 12, index j in cell 13.
**BUILD, by phase, ONE cell per step:**
- 0 ZERO: j < 16: count[j] := 0. At 16 → phase 1, j := 0.
- 1 COUNT: j < N: ℓ := src[j]; if ℓ ≠ 0, count[ℓ] += 1. At N → phase 2, j := 1, code := 0, first[0] := 0, offs[0] := 0.
  (S4's bl_count[0] := 0 holds because length 0 is never counted.)
- 2 NEXT: j ≤ 15: code := 2·(code + count[j−1]); first[j] := code; offs[j] := offs[j−1] + count[j−1]; slot[j] := offs[j].
  At 16 → CHK = 1: phase 3, j := 1, left := 1, rest := 0, total := 0; CHK = 0: phase 4, j := 0.
- 3 LEFT (S4's checks, in S4's order): j ≤ 15: left' := 2·left − count[j]; left' < 0 → reason "over-subscribed", REJECT; else
  left := left', total += count[j], and rest += count[j] when j ≥ 2. At 16: exempt := by the variant — normal: count[1] = 1 ∧
  rest = 0; strict: false; dist: (count[1] = 1 ∧ rest = 0) ∨ total = 0. left > 0 ∧ ¬exempt → reason "incomplete", REJECT;
  else phase 4, j := 0.
- 4 SYMS: j < N: ℓ := src[j]; if ℓ ≠ 0, syms[slot[ℓ]] := j and slot[ℓ] += 1. At N, by TGT: CL → mode LENS (its line before
  its code); L → TGT := 2, phase 0, j := 0 (still BUILD); D → mode SYM.
- The variant by TGT: CL strict; L normal; D dist when DYN = 1, normal when DYN = 0 (S5's `fixedCodes lit` calls `code` with
  the default mode for both tables).
**FIXLENS's hand-off gains TGT := 1 and DYN := 0** (it is re-proved; nothing else in it changes). DHDR's path sets DYN := 1 and
CHK := 1.
**DECODE (S4's `decodeGo`, MSB-first), ONE bit per step.** Cursor-3, 5 cells at `X = IN + n + OUTMAX + 1393` (after the code
tables): X+0 ℓ · X+1 v · X+2 TGT · X+3 ret · X+4 sym. A mode that decodes writes ℓ := 1, v := 0, TGT, ret, and sets mode :=
DECODE. One step: byte ≥ n → reason "truncated", REJECT. Else read bit x exactly as READ does (input byte, table cell,
cursor advanced with a carry), v' := 2·v + x, f := first[ℓ], c := count[ℓ] of TB(TGT); f ≤ v' < f + c → sym :=
syms[offs[ℓ] + v' − f], mode := ret; else ℓ = 15 → reason "invalid code", REJECT (decodeGo's fuel 0 reads no bit); else
ℓ += 1, v := v'.
**S-8's falsifier is amended:** "a mode other than READ **or DECODE** that loads from the bit table".
**What would show this wrong:** a build phase with more than one cell written per step beyond its counters; a check made in an
order other than S4's; a decode that reads a bit after ℓ = 15 fails.

### S-11 (amendment 5, 2026-11-11, the 63rd head). DECLARED before any BUILD code (FIXLENS's hand-off is re-proved with it).
**BUILD's per-target values live in cells, written where the target is set, instead of being re-derived by branching on TGT at
every step** (S-10 had BUILD branch on TGT for its source, its length and its table, which triples every phase lemma). Cursor-3
gains four cells: X+5 SB (the source's first cell) · X+6 NN (its length) · X+7 TBB (the table's first cell) · X+8 VAR (0 normal,
1 strict, 2 dist); all are cell indices relative to `world`'s base.
- FIXLENS's hand-off writes SB := IN+n+OUTMAX, NN := 288, TBB := TB(1), VAR := 0, besides S-10's TGT := 1 and DYN := 0.
- SYMS's end at TGT = 1 writes TGT := 2, SB := IN+n+OUTMAX+HLIT, NN := HDIST, TBB := TB(2), VAR := 2 if DYN = 1 else 0.
- The CL target's hand-off (CLREAD's end) writes TGT := 0, SB := IN+n+OUTMAX+318, NN := 19, TBB := TB(0), VAR := 1.
- Every BUILD phase reads SB, NN, TBB and VAR from those cells, and branches only on its own phase and data.
S-10's semantics are unchanged: the values in the cells are exactly what S-10 derived from TGT.

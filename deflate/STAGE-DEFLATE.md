## What is built (saltbuild EXIT=0 at df-077; audit df-audit-017: 162 of 162 theorems within the standard three)
- `VIRDeflate/Bits.lean` (the rest group): S1's reader (`bit`, `bits`, `align`) as S1 writes it, with `>>>` and `&&&`, over
  `ReaderT Env (StateT St (Except String))`. Also D4's recursion: `bitAt`, the bit of a byte, using `Int` `sub`, `lt`, `add` and
  `mul` only. **`bitAt_eq`**: on every byte b < 256 and i < 8, `bitAt b i = (b >>> i) &&& 1`. `stripTop_eq` is the general
  statement: the recursion is the remainder mod 2^(i+1) on its range.
- `VIRDeflate/Huffman.lean` (the canonical-code group): S4's `code` with its two REJECTs and `decode`. There are three modes
  for the incomplete clause. `normal` is S4 as written. `strict` is S6's code-length code ("no exception"). `dist` is S4's
  note: an all-zero distance code is accepted.
- `VIRDeflate/Kraft.lean` (the canonical-code group, with Huffman.lean), green at df-027. With F ℓ = next_code[ℓ] + bl_count[ℓ]:
  - `nextCodes_succ` is S4's loop: F(ℓ+1) = 2·F ℓ + bl_count[ℓ+1]. `F_eq_sum`: F ℓ = Σ_{k ≤ ℓ} bl_count[k]·2^(ℓ−k).
  - `leftAfter_eq`: S4's `left` is 2^15 − F 15, and the loop rejects iff F 15 > 2^15.
  - **`oversubscribed_iff`**: "over-subscribed" iff the Kraft sum exceeds 1.
  - **`complete_iff`**: `left = 0` iff the Kraft sum is exactly 1.
  - **`prefix_free`**: no code at a shorter length is a prefix of a code. With `lookup_some`, that is decode's uniqueness.
  - `codes_fit`: when the code is not over-subscribed, every ℓ-bit code is below 2^ℓ.
  - **`complete_covers`** (df-032, STATUS 294) is completeness's converse. When `left = 0`, every 15-bit string has, at some
    length, its leading bits equal to a code that decode's test accepts. With `prefix_free`, that length is unique.
    - The proof tiles [0, 2^15) by the per-length intervals, using next_code[ℓ+1] = 2·F ℓ.
    - No new mutant was run for it. The shift-0 mutant breaks `nextCodes_succ`, which it rests on.
  - Mutants, each on the definition AND its restatement together (Huffman's loop and Kraft's step):
    - shift by 0 instead of 1 is red inside `ncLoop_inv` (df-mutant-011);
    - `left' ≤ 0` instead of `< 0` is red inside `leftLoop_eq` (df-mutant-012);
    - the unmutated concatenation in the same sub-namespace is GREEN (df-mutant-010).
- `VIRDeflate/Spec.lean` (the rest group): S2, S3 and S5–S8, in two readings (`inflateLit`, `inflate`) by DEFLATE-E1. Below.
- `VIRDeflate/Run.lean` (the rest group): **GENERATED by `deflate/gen_run.py` from the corpus bytes**, digest-checked against
  the manifest (idiom law 1). `--check` gives rc 0. Its population is the 5 class (i) streams, the 7 crafted class (iii)

  exactly the manifest's bytes, or REJECT. The reasons are printed by `#eval` into `logs/df-007.log`, not asserted (S8).
- **Axioms** (df-audit-003): 29 of 29 theorems are within the standard three (3 at propext · Classical.choice · Quot.sound,
  26 at propext only). The controls below ran at df-audit-002's population (27). Controls:

## The L2 step program, begun (STATUS 292; declarations in DECLARATIONS-DEFLATE.md, written before this file)
- `VIRDeflate/Step.lean` holds D4's bit-of-a-byte as an L2 term: `POW` and `STRIP` are pure `fix` terms using only
  `sub`/`lt`/`le`/`add`/`mul`, and `bitProg v i` combines them. It runs under L2's own `run₂`.
- **Measured, and a route abandoned. Proving `bitProg = bitAt` on every byte by KERNEL EVALUATION does not scale:**
  - one declaration over all 2,048 cases reached 16 GB RSS at 11 min. I stopped it by pid (df-030, a registered executor,
    retired with its landing read);
  - one bit index, 256 cases, under saltbuild `--cap 8000`, aborted at 8 GB in 19 s (df-probe-002);
  - 2 cases take ~3 s, startup included (df-probe-001).
  The kernel's cache grows per case.
- **REPLACED BY A GENERAL PROOF at df-048 (audit df-audit-009): `bitProg_spec`. For every byte b < 256 and every i < 8,
  `bitProg b i` steps, under L2's own relational semantics `Steps₂`, to `ret ((b >>> i) &&& 1)`. D4's L2 recursion IS S1's bit.**
  - It is built from compositional lemmas, each stated in the `let` context its callers use: `steps_run` (a computed
    straight-line run is reached), `pow2_steps` (induction on k) and `strip_steps` (induction on n; the recursion is a TAIL
    call, so it lands back in the caller's context). These are the run lemmas Safety and Correct need.
  - Mutant: STRIP's test `<` → `≤` in the L2 term is red INSIDE `strip_steps` (df-mutant-014). The unmutated copy is GREEN
    (df-mutant-013).
  - **Typed (df-051): `bitProg_typed`, `POW_typed`, `STRIP_typed`.** `bitProg v i` is a closed, well-typed L2 term at ⊢₂, with
    Δ = ∅ and no capability anywhere. Both `fix` bodies are checked with Δ = ∅ by the rule itself. That is D4's "≥ 1 `fix`",
    as an L2 fact.
  - **`BITc`** is the bit of a byte as ONE closed `fix` atom, the form the step program calls. **`bit_steps`** (df-054…056):
    `let x = BITc((b, i)) in e₂` steps to `e₂[bitAt b i / x]` for i ≤ 7. **`BITc_typed`**: closed, at ⊢₂. A `fix` rule that
    supplies its own empty mask (`fix_typed`) was added to the typing tactic.
  - **The world and the named layer (S-1, S-4):**
    - `World σ p L f`: ONE region of L cells, contents f. L is a parameter, where L3's was fixed at 87. `World.store` keeps it.
    - `closeAt` closes a step at ⟨p⟩.
    - `NA`/`NT` compile to `Tm₂` with `fix` atoms, `app` and pairs. A one-load smoke run is evaluated by `simp` on a symbolic
      world (`smoke_run`).
  - **S-7, declared BEFORE any mode code (vir dd073cf):** the TABLE mode fills a 2,048-cell bit table by one `BITc` call per
    step, so every later mode reads a bit as one `load`, and their lemmas are `simp`-evaluable runs.
  - **`table_step`: the FIRST MODE's one-step lemma** (df-066). From a world with counters (tb, ti), tb < 256, ti ≤ 7, ONE
    step writes `bitAt tb ti` at `BT + 8·tb + ti`, advances the counters with a carry, sets the mode to HDR when tb reaches 256,
    and returns ⟨p⟩. The resulting store is given exactly.
    - `steps_via_bit` is the combinator that makes this short: run k computed steps to a `BITc` call, take the call by
      `bit_steps`, continue. The continuation is never written out; unification takes it from the computed run.
    - Mutant: the table index `8·tb` → `7·tb` is red INSIDE `table_step` (df-mutant-016: lines 385/389/393). The unmutated
      copy is GREEN (df-mutant-015). A one-line attribution grep first named the wrong line; reading the log corrected it.
  - **S-8, declared BEFORE any code for the modes it touches (vir 9a79768):** a bit-serial `READ` mode reads every LSB-first
    field ONE bit per step into acc (k, wt, ret in cursor-2 cells 2068–2071; the input moves to 2080). HDR reads BFINAL and
    BTYPE as two fields, since R-c has no primitive to split one 3-bit field. `FIXLENS` is named for the S5 lengths, which S-2
    left without a mode. Huffman DECODE (MSB-first) is NOT covered and owes its own line.
  - **`readbit_step` / `readbit_trunc`: truncation and the carry, proved ONCE** (df-072). With byte < n, input cell v < 256 and
    table cell `8·v + bi` = t, one step adds t·wt to acc, doubles wt, counts k down, advances (byte, bit) with a carry, and sets

## Limits, declared
- ~~The fuel argument~~ **DISCHARGED at df-022 (audit df-audit-005): FUEL ADEQUACY for all three of S's unbounded loops.**
  `huffLoop_fuel`, `lensLoop_fuel` and `blocks_fuel` (Spec.lean, §Fuel) each say: from any state, any two fuels above the unread
  bits give the same run. `huff_adequate`, `lensLoop_adequate` and `run_adequate` say the spec as written (fuel = unread bits + 1
  at entry) equals the loop at ANY such fuel. **So `inflate` and `inflateLit` are S, with no fuel caveat.**
  - The proof rests on progress: `bit` and `decode` move the bit position forward from inside the input (`Adv`); every other
    step, including the stored copy's `set` and the block bodies, never moves it back (`Mono`, via the start-state form `MF`).
  - Mutant: a block header reading `bits 0` for BFINAL is red INSIDE `blocks_fuel` at its progress step (df-mutant-009). The
    unmutated copy in the same sub-namespace is GREEN (df-mutant-008).

    against vir d3f4b39.
- ~~The code representation~~ **DISCHARGED at df-012 (audit df-audit-004): `lookup_codeOf` and `lookup_some` (Huffman.lean, D5's
  group).** For every length ℓ in 1..15, the test `decodeGo` makes at ℓ (`lookup`, tied to `decodeGo` by `decodeGo_succ`) maps
  the code S4 assigns symbol i (`codeOf`: next_code[ℓ] plus the number of earlier symbols of length ℓ) to i. Conversely, any
  value it maps to i is that code, and lens[i] = ℓ. `nextCodes` is shared by both sides, and it is S4's loop as written.
  Mutants are red inside the proofs: symbols taken in decreasing index (df-mutant-006, in `symsOf_eq`) and `decodeGo`'s range
  test widened by one (df-mutant-007, in `decodeGo_succ`). The unmutated copy in the same sub-namespace is GREEN
  (df-mutant-005). That green is the control that the method is sound: df-mutant-003/004 were spurious reds, because a renamed
  namespace lost `M` and `reject`. They are kept in the logs and are not counted as controls.
